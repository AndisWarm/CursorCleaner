# Cursor Cleaner 功能介绍与名词解释

Cursor Cleaner 是一个面向 Windows 的 Cursor 会话维护工具，提供 **TUI**（终端交互界面）和 **CLI**（命令行）两种使用方式。它直接读取 Cursor 本地会话数据库（`state.vscdb`），用于查看聊天记录、备份数据库、清理已归档会话和无效残留数据。所有数据只在本机处理，不会上传到网络。

---

## 一、名词解释

### 1. 核心数据文件

| 名词 | 说明 |
| --- | --- |
| `state.vscdb` | Cursor 的会话数据库（SQLite 格式）。默认位于 `%APPDATA%\Cursor\User\globalStorage\state.vscdb`，账号登录后还会在 `%APPDATA%\Cursor\User\workspaceStorage\<workspace>\state.vscdb` 各存放一份。工具会同时扫描这两处。 |
| `conversation-search.db` | 会话搜索索引，供 Cursor 的聊天搜索功能使用。删除后 Cursor 下次启动会自动重建。 |
| `-wal` / `-shm` | SQLite 的预写日志与共享内存文件。Cursor 运行时会先写 WAL 再合并进主库，因此备份时必须连同这两个文件一起备份，否则可能丢失未合并的数据。 |

### 2. 会话数据的三处存放位置

一个会话的完整数据分散在三处，工具需要将它们合并才能得到完整视图：

| 位置 | 内容 | 作用 |
| --- | --- | --- |
| `composerHeaders` 表 | 每行一个会话的元信息（标题、时间、`isArchived` 归档标记） | 旧版会话列表 |
| `ItemTable` 镜像（`composer.composerHeaders` / `composer.composerData`） | 侧边栏会话列表的镜像副本（含 `isArchived`） | 新版 Cursor 的实际会话列表，旧表已停止更新 |
| `cursorDiskKV` 正文键 | 聊天正文本体，键名前缀包括 `composerData:`、`composerVirtualRowHeights:`、`bubbleId:`、`checkpointId:`、`ofsContent:` | 消息内容，体积最大 |

> 同一个 composer 的元数据和正文可能跨 global/workspace 两个数据库存放，工具会跨库合并并去重。

### 3. 会话状态分类

根据上述三处数据的存在/缺失情况，会话被分为四类：

| 状态 | 判定条件 | 含义 | 能否看到内容 |
| --- | --- | --- | --- |
| **归档**（`ARCHIVED`） | 表或镜像标记 `isArchived=1` | 用户或 Cursor 主动归档的历史会话 | 可查看 |
| **未归档**（`ACTIVE`） | 表/镜像存在且未归档；或仅在镜像中存在且有正文 | 正常活跃会话 | 可查看 |
| **残留**（`MIRROR_ONLY`） | 仅在镜像中存在，且没有任何正文键 | 空壳：列表里还有名字，正文已丢失（如删除过程中断遗留），点开为空 | 不可查看 |
| **孤儿**（`CONTENT_ONLY`） | 表、镜像均无，只剩正文键 | 死数据：列表已被删除，但聊天正文没被清理，白白占用磁盘 | 不可查看 |

> **重要**：新版 Cursor 只写 `ItemTable` 镜像、`composerHeaders` 表已停止更新，所以"镜像有、表没有"的会话只要**有正文**就视为正常活跃会话，不会被误判为残留。只有"镜像有但无任何正文键"的空壳才叫残留。

### 4. 其他术语

| 名词 | 说明 |
| --- | --- |
| 隐藏空占位（draft） | Cursor 账号登录后产生的空草稿/占位副本，通常与真正会话同名同工作区但没有消息正文，会造成"一条对话显示两次"。工具自动隐藏它们，仅保留有正文的记录；`delete-archived` 清理时仍会处理。 |
| 子 agent 会话（subagent） | Cursor 内部子 agent 产生的 composer，不作为主会话展示。 |
| `composerId` | 会话的唯一标识（UUID），也是正文键名中的 UUID 段，用于跨表关联。 |
| VACUUM | SQLite 的数据库压缩操作。删除数据后执行，回收磁盘空间、减小文件体积。 |
| 镜像修复（repair-mirror） | 把表中存在但镜像缺失的活动会话重新补回镜像，修复"侧边栏看不到会话"的问题。 |

## 二、功能总览

### 1. 会话扫描与分类（preview）

扫描 `globalStorage` 和全部 `workspaceStorage` 下的 `state.vscdb`，跨库合并同一会话，输出四类统计：已归档 / 镜像残留（空壳）/ 正文孤儿 / 未归档。

### 2. 查看聊天记录（TUI 按 `v`）

将 `cursorDiskKV` 中的 composerData 索引与 bubble 正文跨库还原为按时间排序的聊天记录，渲染为 Markdown 展示，支持：

- 用户/助手消息、思考过程（thinking）、工具调用摘要（名称、状态、参数）
- UTC 时间自动转换为本地时间
- 后台线程加载，长会话不卡界面；防止重复按键导致页面重复堆叠

聊天记录页面支持把当前会话导出为 Markdown 文件（按 `e`，可自定义保存路径）。导出内容由独立的美化模块（`conversation_markdown_formatter.py`）在**写入文件之前**生成：

- 每条用户消息（对应右侧圆点索引）作为二级标题分组，其后的助手消息以三级标题归入该分组，直到下一条用户消息
- 代码块原样保留（含语言标识，围栏自动闭合），列表、引用、链接、行内代码等格式完整保留；消息内部标题自动降级，避免破坏文档层级
- 会话信息只记录原始数据中确实存在的日期、消息数量与参与者，不编造内容；空消息输出"此消息为空"占位
- 纯函数式转换，不修改原始对话数据；只影响 Markdown 导出，其他导出格式不受影响

### 3. 清理无效数据（delete-archived，核心功能）

一键删除**已归档会话 + 镜像残留 + 正文孤儿**，三种数据一并处理：

- 删除 `composerHeaders` 表行
- 从 `ItemTable` 镜像中移除条目（保留活动会话）
- 删除 `cursorDiskKV` 中该会话的全部正文键（含无 composerId 写法的 `bubbleId:<bid>`）
- 单事务提交后执行 VACUUM 压缩数据库

### 4. 自动备份与恢复

- 删除前**自动备份**所有已发现数据库的三件套（`state.vscdb`、`-wal`、`-shm`）到 `*.bak-<时间戳>`
- 支持手动备份（`backup`）与恢复（`restore`，列出备份列表按编号选择）

### 5. 危险操作防护

- **运行检测**：写操作前检测 Cursor.exe 是否在运行，未退出则拒绝执行（可用 `--force` 跳过，有备份兜底）
- **确认提示**：删除/清空/恢复前需确认（CLI 用 `--yes` 跳过）
- `wipe-all` 清空全部会话前有醒目警告

### 6. 其他功能

| 功能 | 说明 |
| --- | --- |
| `purge-index` | 删除 `conversation-search.db` 搜索索引，Cursor 下次启动自动重建 |
| `repair-mirror` | 修复活动会话未出现在侧边栏镜像中的问题 |
| `--db` 指定数据库 | 测试用，指定后只读该文件，不再自动扫描 workspaceStorage |
| TUI 自动刷新 | 每 5 秒通过文件指纹检测数据库变化，有变化才重新扫描；Cursor 外部归档/取消归档后无需重启即可看到（也可按 `r` 手动刷新） |
| 隐藏空占位去重 | 自动隐藏同名同工作区的空草稿副本，消除列表重复 |

## 三、使用方式

### TUI（终端界面）

```bash
python cursor_cleaner.py
```

或双击 `start_cursor_cleaner.bat`。

| 按键 | 功能 |
| --- | --- |
| `Space` | 勾选/取消当前会话 |
| `A` / `N` | 全选当前筛选结果 / 取消全选 |
| `V` | 查看当前会话聊天记录（`Q`/`Esc` 返回） |
| `D` | 删除勾选的会话（先自动备份，要求 Cursor 已退出） |
| `B` | 备份数据库 |
| `R` | 立即刷新会话列表 |
| `Q` | 退出工具 |

顶部提供筛选按钮（全部 / 归档 / 残留 / 孤儿 / 未归档），状态栏实时显示 Cursor 运行状态、数据库大小与各类会话数量。

### CLI（命令行）

```bash
# 预览会话分类
python cursor_cleaner.py --op preview

# 删除已归档会话 + 残留 + 孤儿（核心功能，--yes 跳过确认）
python cursor_cleaner.py --op delete-archived --yes

# 其他操作
python cursor_cleaner.py --op backup
python cursor_cleaner.py --op restore
python cursor_cleaner.py --op wipe-all --yes        # 危险：清空全部会话
python cursor_cleaner.py --op purge-index
python cursor_cleaner.py --op repair-mirror

# Cursor 未退出时强行执行（有备份兜底）
python cursor_cleaner.py --op delete-archived --yes --force

# 指定数据库（测试）
python cursor_cleaner.py --db "D:\test\state.vscdb" --op preview
```

### CLI 操作一览

| 操作 | 说明 | 危险度 |
| --- | --- | --- |
| `preview` | 扫描并分类会话 | 只读 |
| `delete-archived` | 删除归档会话 + 残留 + 孤儿 | 中（自动备份） |
| `backup` | 备份当前数据库 | 只读 |
| `restore` | 从备份恢复 | 中（覆盖当前库） |
| `wipe-all` | 清空全部会话 | 高（不可逆） |
| `purge-index` | 清理会话搜索索引 | 低（自动重建） |
| `repair-mirror` | 修复会话列表镜像 | 中（自动备份） |

## 四、环境要求与数据位置

- Windows 10/11，Python 3.10+，已安装 Cursor
- 依赖：`pip install -r requirements.txt`（含 textual，TUI 必需）

默认数据位置：

```text
%APPDATA%\Cursor\User\globalStorage\state.vscdb
%APPDATA%\Cursor\User\workspaceStorage\*\state.vscdb
%APPDATA%\Cursor\User\globalStorage\conversation-search.db
```
